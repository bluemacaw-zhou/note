# 课程音频自动笔记：理论与架构

> 当前运行环境：Mac Mini（M4）宿主机
> 实践记录：[[2026-03-15_课程音频自动笔记实践记录]] · 工作流规划：[[2026-03-15_课程音频自动笔记方案]]

---

## 一、是什么，为什么做

听课的核心痛点：内容转瞬即逝，手动记笔记跟不上语速，课后复盘靠记忆不可靠。

本方案的目标：**播放课程时系统自动录制音轨，转录为文字，再由 AI 生成结构化笔记，自动入库 Obsidian**。

## 三、各组件原理

### 3.1 BlackHole：虚拟音频驱动

BlackHole 是 macOS 的**内核级虚拟音频设备**，挂接在 CoreAudio 框架上。它的工作方式是：

- 作为一个虚拟的音频输出设备出现在系统中
- 任何写入它的音频数据，可以被其他应用作为"输入设备"读取

配合 macOS 的**多输出设备**（Audio MIDI Setup），可以同时将系统音频路由到扬声器和 BlackHole，实现边播放边捕获，不影响收听体验。

> **为什么必须在宿主机**：BlackHole 是 macOS 内核扩展（kext），依赖 CoreAudio，容器层（Linux VM）无法访问。

### 3.2 ffmpeg：音频录制

ffmpeg 通过 `-f avfoundation` 驱动访问 macOS 的 AVFoundation 音频设备，直接读取 BlackHole 的音频流，写入 WAV 文件。

录制命令：
```bash
ffmpeg -f avfoundation -i ":0" -c:a pcm_s16le ~/whisper/audio/<name>.wav
```

- `:0` 表示第 0 个音频设备（BlackHole）
- `pcm_s16le`：无损 16bit PCM，不做实时压缩，避免丢帧

> **为什么必须在宿主机**：需要访问宿主机的 AVFoundation 音频设备，容器内无法访问。

### 3.3 whisper.cpp：语音转录

whisper.cpp 是 OpenAI Whisper 模型的 C++ 实现，支持 Apple Metal GPU 加速。

**工作流程：**
```
.wav 文件
    ↓ 提取音频帧
Mel 频谱图（80维特征）
    ↓ Encoder（Metal GPU）
音频特征向量
    ↓ Decoder（Metal GPU）
Token 序列 → 文字 + 时间戳
    ↓
.srt 字幕文件
```

**模型选择：**

| 模型 | 大小 | 中文准确率 | 速度（M4） |
|------|------|-----------|-----------|
| small | 466MB | 一般，专业词汇易出错 | 快 |
| **medium** | 1.5GB | **推荐，金融/专业内容** | 中等 |
| large | 3GB | 最高 | 慢 |

> **为什么必须在宿主机**：Metal GPU 加速只能在 macOS 原生运行，容器层（Linux VM）跑不了 Metal，速度慢 5-10 倍。

## 四、设计思考

### 4.1 为什么不用 Docker 容器跑 whisper

容器跑在 OrbStack 的 Linux VM 里，Metal GPU 无法穿透。CPU 转录 medium 模型比 Metal 慢约 5-10 倍，1 小时课程要等半小时以上，不可接受。

### 4.2 为什么录 WAV 而不是 M4A

M4A 是有损压缩，ffmpeg 在录制时做实时 AAC 编码，CPU 占用更高且有丢帧风险。WAV 是无损 PCM，边录边写，没有编码开销。whisper.cpp 也原生支持 WAV，无需转换。

### 4.3 为什么不直接用 SRT 而是先纯文字

SRT 带时间戳，适合后续对照原始音频校验。若直接生成文字笔记，时间戳信息丢失，定位原文困难。

## 五、完整流水线

```
课程播放（浏览器/视频）
    ↓ CoreAudio
BlackHole 2ch（捕获）
    ↓
ffmpeg → ~/whisper/audio/<name>.wav
    ↓
whisper-cli（Medium 模型，Metal GPU）→ <name>.srt
    ↓
Claude API（后续）→ 结构化笔记（标题/摘要/要点/TODO）
    ↓
Obsidian（入库）
```
