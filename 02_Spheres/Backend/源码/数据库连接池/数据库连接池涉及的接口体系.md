

## 一、数据库驱动提供的核心接口（JDBC标准）

### 1. **Driver 接口** - 数据库驱动
```
Driver驱动接口：
- connect(url, properties) → 返回Connection对象
- acceptsURL(url) → 判断是否支持该URL
```

### 2. **Connection 接口** - 数据库连接（最核心）
```
Connection连接接口：
- createStatement() → 创建SQL语句执行器
- prepareStatement(sql) → 创建预编译语句
- commit() → 提交事务
- rollback() → 回滚事务
- close() → 关闭连接（连接池会拦截这个方法）
- isClosed() → 检查连接是否关闭
- isValid(timeout) → 检查连接是否有效
- setAutoCommit(boolean) → 设置自动提交
```

### 3. **Statement 接口** - SQL执行器
```
Statement接口：
- executeQuery(sql) → 执行查询，返回ResultSet
- executeUpdate(sql) → 执行更新操作
- close() → 关闭语句
```

### 4. **ResultSet 接口** - 结果集
```
ResultSet接口：
- next() → 移动到下一行
- getString(columnName) → 获取字符串数据
- getInt(columnName) → 获取整数数据
- close() → 关闭结果集
```

## 二、连接池需要使用的接口

### 1. **DriverManager 类** - 驱动管理器
```
DriverManager工具类：
- getConnection(url, username, password) → 获取原始连接
- registerDriver(driver) → 注册驱动
```

### 2. **DataSource 接口** - 数据源（连接池要实现这个）
```
DataSource接口：
- getConnection() → 获取连接（用户调用）
- getConnection(username, password) → 带认证的获取连接
```

## 三、连接池的实现逻辑

### 连接池内部持有的对象：

```
连接池类 {
    数据结构：
    - 空闲连接队列：Queue<Connection>
    - 活跃连接集合：Set<Connection>
    - 配置参数：最大连接数、最小连接数、超时时间等
    
    核心方法：
    - 初始化连接池() {
        使用 DriverManager.getConnection() 创建初始连接
        放入空闲队列
    }
    
    - 获取连接() {
        如果空闲队列有连接：
            从队列取出
            检查连接是否有效（connection.isValid()）
            如果有效：返回包装后的连接
            如果无效：销毁并创建新连接
        
        如果空闲队列为空：
            如果总连接数 < 最大连接数：
                创建新连接
            否则：
                等待或抛出异常
    }
    
    - 归还连接() {
        重置连接状态（rollback、setAutoCommit等）
        放回空闲队列
    }
    
    - 销毁连接() {
        调用真实的 connection.close()
        从活跃集合移除
    }
}
```

### 连接包装类（关键设计）：

```
包装连接类 实现 Connection接口 {
    持有：
    - 真实的Connection对象
    - 所属的连接池引用
    
    重写close()方法：
        不调用真实connection.close()
        而是调用 连接池.归还连接(this)
    
    其他方法（createStatement、prepareStatement等）：
        直接委托给真实Connection对象
}
```

## 四、完整流程描述

### 初始化阶段：
1. 加载数据库驱动（Class.forName 或 SPI自动加载）
2. 使用 DriverManager.getConnection(url, user, password) 创建若干个真实连接
3. 将真实连接包装成代理连接，放入空闲队列

### 使用阶段：
1. 用户调用 connectionPool.getConnection()
2. 连接池从空闲队列取出一个包装连接
3. 用户使用连接执行SQL操作
4. 用户调用 connection.close()
5. **实际执行的是：连接池.归还连接()，而非真正关闭**
6. 连接被放回空闲队列，供下次使用

### 销毁阶段：
1. 连接池关闭时
2. 遍历所有连接，调用真实的 connection.close()
3. 清空队列和集合

## 五、关键点总结

- **数据库暴露的最核心接口是 Connection**，连接池的本质就是管理这个对象
- **连接池不直接返回真实Connection**，而是返回包装后的代理对象
- **拦截close()方法是连接池的核心技巧**，让连接回到池中而非真正关闭
- 需要定期检查连接有效性（connection.isValid()）
- 需要处理连接泄漏、超时、并发等问题
