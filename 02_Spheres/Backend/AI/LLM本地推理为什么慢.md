# LLM 本地推理为什么慢

## 推理的两个阶段

LLM 推理分为两个阶段，慢的是第二个：

```
Prefill（输入处理）
  把整个 prompt 的 token 一次性并行计算
  速度快，与输入长度关系不大

Decode（逐 token 生成）← 瓶颈在这里
  每次只能生成 1 个 token
  必须等上一个生成完才能生成下一个
  输出有多少 token，就要循环多少次
```

翻译 1 页英文 ≈ 输出 500 中文字符 ≈ 500 次循环。

---

## 为什么内存带宽是瓶颈

每生成一个 token，都要把**整个模型权重**读一遍：

```
生成第 1 个 token：把 20GB 模型权重从内存读一遍
生成第 2 个 token：再读一遍
生成第 3 个 token：再读一遍
...
```

带宽决定每次读取的速度，因此：

```
吞吐上限（tok/s）= 内存带宽 ÷ 模型大小

M4 统一内存：120 GB/s ÷ 20GB ≈ 6 tok/s
RTX 4090：   1008 GB/s ÷ 20GB ≈ 50 tok/s
H100：       3350 GB/s ÷ 20GB ≈ 167 tok/s
```

---

## 系统内存 vs 显存

| | 系统内存（DDR5） | 显存（GDDR6X） | Apple 统一内存 |
|---|---|---|---|
| 带宽 | ~80 GB/s | 360-1008 GB/s | 120-800 GB/s |
| 角色 | 模型装不进显存时的溢出区 | 模型完整跑在 GPU 上 | CPU/GPU 共享 |

**关键规则：模型只要有一个字节溢出到系统内存，速度就被 DDR 带宽拖死。**

- 显存 > 模型大小 → 快
- 显存 < 模型大小 → 慢，多少系统内存都救不了

## 显存带宽看哪个参数

商品页面找这两行：

```
显存位宽：384-bit
显存频率：21 Gbps

带宽 = 位宽 × 频率 ÷ 8
     = 384 × 21 ÷ 8 ≈ 1008 GB/s（RTX 4090）
```

显存类型与带宽范围：

| 显存类型 | 带宽范围 | 代表产品 |
|---------|---------|---------|
| GDDR6 | 300-600 GB/s | RTX 3060/3080 |
| GDDR6X | 600-1008 GB/s | RTX 3090/4090 |
| HBM2e | 1600-2000 GB/s | A100（数据中心） |
| HBM3 | 3000-4000 GB/s | H100（数据中心） |

A100/H100 不在消费品渠道销售，只能通过云服务商租用。**消费级天花板是 RTX 4090（24GB，1008 GB/s）**。

## Apple Silicon 的特殊性

M 系列芯片没有独立显存，CPU/GPU/Neural Engine 封装在同一颗芯片上，共用统一内存：

```
带宽由芯片型号决定，与主板无关：

M4        120 GB/s   →  ~6 tok/s（32b 模型）
M4 Pro    273 GB/s   →  ~13 tok/s
M4 Max    400 GB/s   →  ~20 tok/s
M4 Ultra  800 GB/s   →  ~40 tok/s
```

优势：32GB 全部可用于模型，不像 PC 需要区分系统内存和显存。
劣势：带宽上限远低于专业显卡。

---

## 批处理为什么能摊薄带宽成本

单用户场景：batch size = 1，每次循环只产出 1 个 token。

云服务的做法：同时处理多个用户请求，batch size = 32，同样读一遍模型权重，产出 32 个 token，相当于每个用户享受 32 倍吞吐。这是云端 API 快的核心原因之一。

## 本地推理的合理使用场景

| 场景 | 适合本地 | 原因 |
|------|---------|------|
| 交互式问答、代码辅助 | ✓ | 输出短，延迟可接受 |
| 隐私数据处理 | ✓ | 数据不出本机 |
| 异步后台 skill（笔记整理等） | ✓ | 不需要实时反馈 |
| 大批量翻译（千页文档） | ✗ | 总 token 量大，耗时以天计 |
| 需要快速出结果的任务 | ✗ | 带宽瓶颈无法绕过 |

大批量任务应使用云端 API（如 Gemini 2.5 Flash），本地模型保留给日常高频短任务。
