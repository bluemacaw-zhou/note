# 四种求导方法与自动微分

> 总览 [[day02_00_总览|day02]] · ← [[day02_04_两层网络的手写实现|手写两层网络]] · 下一块 → [[day02_06_从手写到框架的六步演进|六步演进]]

**为什么需要**：04 的手写求导又累又容易错。计算机求导有四种办法，框架只选了其中一种。

## 四种方法对比

| 方法 | 做法 | 问题 |
|---|---|---|
| 手工微分 | 人推公式，再写进代码 | 每改一次模型就要重推，容易出错 |
| 数值微分 | `f′(x) ≈ (f(x+h) − f(x)) / h` | 有截断和舍入误差；每个参数都要单独算一遍，参数一多就太慢 |
| 符号微分 | 把整个表达式交给代数系统求导 | **表达式膨胀**：嵌套几层后，导数式子变得极长 |
| **自动微分** | 把程序拆成加、乘、exp 等**基本算子**，每个算子的导数已知，再用链式法则组合 | — 框架都用它 |

**自动微分介于后两者之间**：每个基本算子用的是符号导数（精确），组合时却代入具体数值（不展开表达式），所以既精确又不膨胀。day01_10 的计算图就是它的工作方式。

## PyTorch 里的用法

```python
x = torch.tensor(2.0, requires_grad=True)   # 标记：要对 x 求导
y = 2 * x ** 2 + 3
y.backward()                                 # 沿计算图反向传播
print(x.grad)                                # tensor(8.)
```

> **勘误**：课件文字写「y = 2x² + 3，在 x = 2 时导数为 8」，但代码（以及 `demo_02/test09.py`）写的是 `y = 2*x + 3`，实际输出为 `tensor(2.)`。实测：`2*x+3` 的梯度是 2.0，`2*x**2+3` 的梯度才是 8.0。

## test03 的三个细节

| 写法 | 原因 |
|---|---|
| 输入 x、y 不设 `requires_grad` | 不需要对数据求导，只对参数求导 |
| 更新写在 `with torch.no_grad():` 里 | 否则「参数 −= lr·梯度」这一步本身也会被记进计算图 |
| 每轮后 `w.grad.zero_()` | `.grad` 默认**累加**，不清零就会把上一轮的梯度也算进去 |
