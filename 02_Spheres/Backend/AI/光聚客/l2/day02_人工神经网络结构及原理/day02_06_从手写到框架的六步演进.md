# 从手写到框架的六步演进

> 总览 [[day02_00_总览|day02]] · ← [[day02_05_四种求导方法与自动微分|自动求导]] · 下一块 → [[day02_07_参数量的通用公式|参数量]]

**为什么需要**：day01_12 给的是一张「PyTorch 对照手写」的最终对照表。demo 的 test01～06 用**同一个任务**，每次只换掉一样东西，能看清框架是怎样一点点接手的。

任务：`64 个样本 × 1000 维 → 100 维隐藏层（ReLU）→ 10 维输出`，MSE 损失，训练 500 轮。

| 文件 | 换掉了什么 | 还要手写的 |
|---|---|---|
| test01 | 纯 numpy | 前向、loss、**反向**、更新 |
| test02 | numpy 数组 → torch 张量，可上 GPU | 同上 |
| test03 | 反向 → `loss.backward()` | 更新、清零 |
| test04 | 网络 → `nn.Sequential`，loss → `nn.MSELoss` | 更新（遍历 `model.parameters()`） |
| test05 | 加 `device` 自动选 GPU / CPU | 同上 |
| test06 | 更新 → `optim.Adam` + `optimizer.step()` | **只剩循环骨架** |

最后剩下的循环骨架，正是 day01_12 表格里的五步：前向 → loss → `zero_grad` → `backward` → `step`。

## 为什么 test01 的学习率是 1e-6，test04 却是 1e-4？

- test01 的 loss 是 `square(...).sum()`，对 64×10 = 640 个误差**求和**；
- test04 的 `nn.MSELoss()` 默认**求平均**。

求和的梯度正好是求平均的 **640 倍**（实测比值为 640.0），所以学习率要相应缩小。**换损失的归约方式时，学习率要跟着改。**

## 单层线性回归实例（课件实例一 / test08）

数据 `x = [1, 2, 3]`，`y = [3, 5, 7]`，真实关系是 `y = 2x + 1`，预测 `x = 4`，应得 9。

| 配置 | 实测 `model(4)`（5 个随机种子） |
|---|---|
| 课件：SGD，lr = 0.01，100 轮 | 8.79～9.39，**还没收敛** |
| test08：Adam，lr = 0.01，1600 轮 | 8.65～9.00 |
| SGD，lr = 0.01，2000 轮 | 全部 9.00，w = 2.0，b = 1.0 |

课件说的「应接近 9.0」，100 轮做不到，要加大轮数。test08 换成 Adam 后结果并没有更稳定，**Adam 不总是比 SGD 好**（见 [[day02_08_训练调优的五个讨论|08]]）。

## 高级 API 的两个补充（课件末尾）

- `nn.Sequential`：把多个层串成流水线，前一层的输出就是后一层的输入。
- 手动初始化：`net[0].weight.data.normal_(0, 0.01)`，`net[0].bias.data.fill_(0)`，与 04 的「乘 0.01」是同一个思路。

> test07 写的 `MSELoss(size_average=False)` 在新版 PyTorch 中已经废弃，应改为 `MSELoss(reduction='sum')`。
