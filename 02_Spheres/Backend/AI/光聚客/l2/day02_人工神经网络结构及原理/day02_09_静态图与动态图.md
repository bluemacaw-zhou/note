# 静态图与动态图

> 总览 [[day02_00_总览|day02]] · ← [[day02_08_训练调优的五个讨论|调优]] · 终点

**为什么需要**：day01_10 把计算图当作求导工具，day01_12 只在时间轴上提到「静态图 / 动态图」。这里讲清楚框架为什么需要计算图，以及两种图的区别。

## 框架用计算图做四件事

| 功能 | 说明 |
|---|---|
| 统一表达 | 用户写 Python，硬件只认 C/C++。计算图是两者之间统一的中间表示 |
| 自动求梯度 | 沿着图反向走一遍，就能得到每个参数的梯度（[[day02_05_四种求导方法与自动微分\|05]]） |
| 管理变量生命周期 | 知道每个中间值什么时候产生、什么时候不再需要，从而及时释放内存 |
| 优化执行 | 分析算子之间的依赖，找出可以并行的部分 |

**是什么**：节点是**算子**（Matmul、Add、ReLU…），有向边是**张量**。它必须是**有向无环图**（DAG），因为有环就会无限循环。

## 两种生成方式

| | 静态图 | 动态图 |
|---|---|---|
| 核心 | **先定义，再执行** | **边执行边建图** |
| 过程 | 前端代码 → 编译成完整的图 → 图优化 → 执行 | 每执行一个算子，就立刻算出结果，并记下它的反向算子 |
| 代表 | TensorFlow 1.x（`placeholder` + `Session.run`） | PyTorch |
| 中间结果 | 拿不到 | 随时可以 print |
| 调试 | 难 | 易 |
| 控制流 | 要用专门的语法，如 `tf.cond` | 直接用 Python 的 `if` / `for` |
| 性能 | 可以做整图优化，性能更好 | 图优化受限 |
| 部署 | 可以直接部署 | 不能直接部署 |

## 动态图的实例：test07 DynamicNet

```python
def forward(self, x):
    h = self.input_linear(x).clamp(min=0)
    for _ in range(random.randint(0, 3)):   # 每次前向，中间层数都随机
        h = self.middle_linear(h).clamp(min=0)   # 同一个层反复使用 = 参数共享
    return self.output_linear(h)
```

**只有动态图能这样写**：每次调用 `forward`，图的层数都不同，框架当场建图、当场求导。静态图要求图结构提前固定。

**PyTorch 怎么补上部署的短板**：用 TorchScript / `torch.compile` 把动态图转成静态图。这就是 day01_12 时间轴上「TF 2.0 动静结合」的思路。
