# 分词与索引

> 总览 [[day03_00_总览|day03]] · ← [[day03_02_模型下载与本地加载|下载与加载]] · 下一块 → [[day03_04_文本生成就是两万选一|输出层]]

**为什么需要**：模型只能做数值运算，不认识汉字。文字必须先切开，再换成数字。

## 第一步：切

![[procreate/分词的两种粒度.png]]

**读图**：同一句话有两种切法。按字切，得到 14 个 token；按词切，得到 9 个 token。课程用的 `bert-base-chinese` 和 `gpt2-chinese` 都是**按字切**。

| | 按字切 | 按词切 |
|---|---|---|
| 词表大小 | 小，常用汉字加符号约 2 万个 | 大，词的组合多得多 |
| 生僻词 | 总能拆成单字，不会遇到不认识的 | 容易遇到词表里没有的词 |
| 序列长度 | 长 | 短 |

## 第二步：查表

![[procreate/分词器把文字变成索引.png]]

**读图**：`vocab.txt` 一共 21128 行，「今」在第 791 行，「天」在第 1921 行（行号从 0 开始数）。分词器做的事情只有查表。

实测 `tokenizer("今天")` 得到 `[101, 791, 1921, 102]`，头尾多出来的是两个特殊标记：

| 编号 | 标记 | 作用 |
|---|---|---|
| 101 | `[CLS]` | 句首 |
| 102 | `[SEP]` | 句尾 |
| 0 | `[PAD]` | 补齐长度 |

**一个容易忽略的细节**：`uer/gpt2-chinese` 用的是 **BERT 的分词器和词表**（实测 `AutoTokenizer` 加载出来的是 `BertTokenizerFast`，词表同样是 21128 行）。BERT 分词器**没有设置结束符**（实测 `eos_token` 为 None），所以生成时要手动指定 `[SEP]`（102）作为结束符。我的改写里写的就是 `eos_token_id=tokenizer.sep_token_id`。
