# 采样参数：temperature、top_k、top_p、do_sample

> 总览 [[day03_00_总览|day03]] · ← [[day03_04_文本生成就是两万选一|输出层]] · 下一块 → [[day03_06_特征空间与词向量|词向量]]

**为什么需要**：如果每次都选概率最大的字，同一个输入永远得到同一句话，而且容易陷入重复。如果完全随机选，又会选到不通顺的冷门字。采样参数就是用来控制这两者之间的平衡。

## temperature：改变分布的形状

![[procreate/温度改变概率分布.png]]

```text
p = softmax(logits / T)
```

**读图**：同样是「今天天气 ___」，

- T = 0.5，「很」的概率从 0.211 升到 0.575，分布变尖，几乎总是选「很」；
- T = 1.5，「很」只剩 0.082，分布变平，冷门字的机会变大。

**排名始终不变**：除以同一个正数，不会改变得分的大小顺序。

> **修正**：课堂笔记写「temperature = 0.7：从前 50 个 token 中**以 0.7 的随机性**随机取一个」。0.7 不是一个随机概率，而是 logits 的**除数**：先用它改变分布的形状，再按改变后的概率去抽。

## top_k、top_p、do_sample：决定从哪些字里抽

![[procreate/三种取词方式.png]]

**读图**：

| 参数 | 候选范围 | 本例 |
|---|---|---|
| `do_sample=False` | 只有概率最大的那一个（贪心） | 永远选「很」，输出固定 |
| `top_k=50` | 概率最高的前 50 个，个数**固定** | 第 51 个以后都被排除 |
| `top_p=0.9` | 从高到低累加概率，**刚好凑够 0.9** 为止 | 0.211 → 0.320 → 0.415 → … 实测要累加到前 38 个 |

**top_p 的个数会随分布变化**（实测，T = 1）：

| 输入 | 凑够 0.9 需要几个候选 |
|---|---|
| 我们去 ___ | 24 个（「的」一个就占了 0.615，分布很集中） |
| 今天天气 ___ | 38 个 |
| 白 ___ | 406 个（后面可以接的字很多，分布很分散） |

模型越有把握，候选就越少，这正是 top_p 比固定的 top_k 更灵活的地方。

> **修正**：课程代码的注释说 top_p=0.9 表示「在可能性最强的 90% 的词中选择」。准确的说法是「**累计概率**达到 90% 的那些词」，不是 90% 数量的词。

**执行顺序**（图右下角）：logits → 除以 T → top_k 截断 → top_p 截断 → 按概率抽一个。

**固定输出**：HuggingFace 不允许设置 `temperature=0`，要得到固定的输出，就设 `do_sample=False`。另外，只有在 `do_sample=True` 时，temperature、top_k、top_p 才会生效，所以我的改写里显式写了 `do_sample=True`。
