## 1. 双向链接系统

### 1.1 什么是双向链接

**双向链接（Bidirectional Links）**是 Obsidian 的核心特性，它允许笔记之间建立**自动关联**。

```
笔记 A → 链接到 → 笔记 B
        ↓ 自动建立
笔记 B ← 反链于 ← 笔记 A
```

### 1.2 双向链接的优势

> [!tip] 为什么需要双向链接？
> **传统笔记**：文档是孤岛，查找依赖记忆和搜索
> **双向链接**：文档是网络，自动发现关联知识

**核心优势**：
- ✅ **自动发现关联**：无需手动维护引用关系
- ✅ **知识图谱可视化**：直观看到知识网络
- ✅ **降低认知负担**：不必记住所有文档位置
- ✅ **促进创意连接**：意外发现知识间的联系

### 1.3 出链 vs 反链

**出链（Outgoing Links）**：
- 当前文档**引用**的其他文档
- 在当前文档中可见
- 你主动创建的链接

**反链（Backlinks）**：
- **引用**当前文档的其他文档
- 在右侧面板中可见
- 系统自动维护

### 1.4 链接类型详解

**1. 文档链接**：
```markdown
[文档名称](文档名称.md)
```

**2. 标题链接**：
```markdown
[文档名称#章节标题](文档名称#章节标题.md)
```

**3. 段落链接（块引用）**：
```markdown
[文档名称^blockid](文档名称^blockid.md)
```

**4. 别名链接**：
```markdown
[完整文档名|显示的简称](完整文档名|显示的简称.md)
```

**5. 嵌入链接**：
```markdown
[被嵌入的文档](被嵌入的文档.md)
[文档名称#特定章节](文档名称#特定章节.md)
```

### 1.5 块引用详解

**创建块引用**：

在任意段落前输入 `^` 和一个标识符：

```markdown
这是一个重要段落 ^important

普通段落，不会被引用

另一个被引用的段落 ^note
```

**引用块**：

```markdown
引用上面的重要段落：
[文档名^important](文档名^important.md)
```

**实际应用**：

```markdown
## 需求背景

项目需要支持用户登录功能 ^req-bg

## 技术方案

基于背景需求 [需求文档^req-bg](需求文档^req-bg.md)，我们选择 JWT 方案
```

## 2. 标签体系设计

### 2.1 标签系统的价值

标签提供了一种**灵活的分类方式**，打破了传统文件夹的层级限制。

> [!info] 标签 vs 文件夹
> **文件夹**：文档只能在一个位置
> **标签**：文档可以有多个标签

**优势**：
- 🏷️ 多维度分类
- 🔍 快速筛选
- 📊 统计分析
- 🎯 精准定位

### 2.2 标签设计原则

> [!warning] 标签设计三原则
> 1. **一致性**：使用统一的命名规范
> 2. **简洁性**：避免过深的层级（建议不超过3级）
> 3. **实用性**：只创建真正会使用的标签

### 2.3 推荐标签体系

#### 按功能分类

```markdown
# 状态/待办
# 状态/进行中
# 状态/已完成
# 状态/已归档
# 状态/阻塞

# 优先级/紧急
# 优先级/高
# 优先级/中
# 优先级/低

# 类型/需求
# 类型/设计
# 类型/开发
# 类型/测试
# 类型/文档
# 类型/会议

# 团队/前端组
# 团队/后端组
# 团队/测试组
# 团队/产品组
```

#### 按项目分类

```markdown
# 项目/用户中心
# 项目/订单重构
# 项目/支付优化
# 项目/数据迁移

# 项目/用户中心/前端
# 项目/用户中心/后端
# 项目/用户中心/测试
```

#### 按技术栈分类

```markdown
# Java
# SpringBoot
# Vue
# MySQL
# Redis
# Docker

# 技术栈/后端/Java
# 技术栈/后端/SpringBoot
# 技术栈/前端/Vue
# 技术栈/数据库/MySQL
# 技术栈/缓存/Redis
```

### 2.4 标签最佳实践

> [!tip] 标签使用技巧
> **在 Frontmatter 中定义**（推荐）：
> ```markdown
> ---
> tags: [需求, 用户认证, 高优先级]
> ---
> ```

**在正文中使用**：
```markdown
本文档描述 #用户认证 功能的详细设计。

相关技术栈: #Java #SpringBoot #JWT
```

**批量标签管理**：

在标签面板中：
- 点击标签查看所有相关笔记
- 右键重命名标签（自动更新所有引用）
- 拖拽创建多级标签

## 3. 反向链接与知识图谱

### 3.1 反向链接面板

**位置**：笔记右侧面板

**功能**：
1. **链接到此文件的笔记**：显示所有引用当前文档的笔记
2. **未链接的提及**：显示包含当前文档名称但未建立链接的文本

### 3.2 未链接的提及

**什么是未链接的提及**：

在笔记 A 中写了笔记 B 的名字，但没有用 `[[]]` 包起来：

```markdown
笔记 A：
在 用户登录需求 中，我们定义了认证流程。
```

**自动转换**：

在反向链接面板中，Obsidian 会自动检测到：
- 未链接的提及：`用户登录需求`
- 点击"链接"按钮，自动转换为：`[用户登录需求](用户登录需求.md)`

### 3.3 关系图谱

**打开图谱**：`Ctrl/Cmd + G`

**图谱类型**：

1. **局部图谱**：显示当前笔记的关联网络
2. **全库图谱**：显示整个知识库的关系网络

**图谱操作**：

| 操作 | 说明 |
|------|------|
| `Ctrl/Cmd + 拖拽` | 旋转视角 |
| `滚轮` | 缩放 |
| `点击节点` | 打开笔记 |
| `拖拽节点` | 调整位置 |
| `右键节点` | 查看相关选项 |

**图谱过滤**：

在图谱设置中可以：
- 按标签筛选
- 按文件夹筛选
- 隐藏孤立节点
- 调整节点大小

## 4. PKM 最佳实践

### 4.1 链接策略

**何时创建链接**：

> [!tip] 创建链接的时机
> **应该链接**：
> - 提及相关概念或术语
> - 引用其他文档的内容
> - 建立知识关联
>
> **无需链接**：
> - 常见词汇（如"用户"、"数据"）
> - 不会再次查看的内容
> - 临时笔记

**链接密度建议**：

```markdown
# 太少链接
用户认证系统包含登录功能。🔴 难以发现关联

# 适度链接
[用户认证](用户认证.md)系统包含[登录功能](登录功能.md)。🟢 清晰的关联

# 过度链接
[用户](用户.md)[认证](认证.md)[系统](系统.md)[包含](包含.md)[登录](登录.md)[功能](功能.md)。🔴 难以阅读
```

### 4.2 标签策略

**标签 vs 链接的选择**：

| 场景 | 使用标签 | 使用链接 |
|------|----------|----------|
| 分类笔记 | ✅ | ❌ |
| 标记状态 | ✅ | ❌ |
| 建立关联 | ❌ | ✅ |
| 组织项目 | ✅ | ✅ 结合使用 |

**示例**：

```markdown
---
tags: [需求, 用户中心, 高优先级]
---

# 用户登录需求

本文档描述 [用户认证](用户认证.md) 功能的需求细节。
```

### 4.3 知识网络构建

**渐进式构建法**：

> [!info] 从小到大的知识网络
> 1. **创建 MOC（Map of Content）**：主题索引页
> 2. **添加核心链接**：链接最重要的相关笔记
> 3. **让网络生长**：自然地添加更多链接
> 4. **定期维护**：查看反链，完善网络

**MOC 示例**：

## 7. 常见问题

### Q1：链接太多会不会影响性能？

**A**：
- 少量链接（<100）：无明显影响
- 中等链接（100-500）：轻微影响
- 大量链接（>500）：可能影响打开速度

**建议**：
- 只链接真正相关的内容
- 使用嵌入而非复制内容
- 定期清理无效链接

### Q2：标签和链接如何选择？

**A**：
- 用**标签**标记：类型、状态、优先级
- 用**链接**关联：相关概念、引用内容

**示例**：
```markdown
---
tags: [需求, 用户中心]
---

# 用户登录需求

相关文档：[概要设计](概要设计.md)
```

### Q3：如何处理重命名后的链接？

**A**：Obsidian 自动处理
- 重命名文件时，自动更新所有链接
- 重命名标签时，自动更新所有引用
- 无需手动维护

### Q4：图谱太乱了怎么办？

**A**：
1. 使用**局部图谱**而非全库图谱
2. 按**标签或文件夹**过滤
3. 调整**节点大小和距离**
4. **隐藏孤立节点**
