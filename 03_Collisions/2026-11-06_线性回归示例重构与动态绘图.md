# linear-demo：把课程代码改造成可观察的教学示例

**实验目标**：把子牙课程的 `ziya-chatgpt-3/chat-1` 迁移成 `nn-lab/linear-demo`，改造成自己读得懂、看得见训练过程的示例。

**边界**：这里只记**代码怎么设计、为什么这样取舍**。学习过程中的概念追问（导数、梯度、backward、学习率）记在 [[02_Spheres/Backend/AI/子牙/2026-10-29_手写ChatGPT_专题一_线性模型与训练闭环|专题一笔记]]。工程迁移和 uv 的细节记在 [[2026-11-06_AI子项目迁移与uv管理|AI 子项目迁移与 uv 管理]]。

## 设计决策的演进

```text
① 统一代码风格 → ② 让训练过程看得见 → ③ 让每个变量读得懂
→ ④ 把绘图抽成结构 → ⑤ 用实验问题决定 demo 的取舍
```

每一步都是被上一步暴露的问题推着走：风格统一后才发现训练看不见；看得见之后才发现读不懂；读懂之后，重复的 demo 就显得多余了。

### ① 统一代码风格（11-06）

> 触发：迁移后的代码是脚本式的，还夹着 ipynb。

**决定**：

| 约定 | 原因 |
|---|---|
| 类组织示例，并提供 `__main__` 入口 | 偏好 Java 式的结构 |
| import 全部放在文件开头 | 不在代码中间穿插 |
| `log.info` 代替 `print` | 统一使用 ai-starter 的日志 |
| 删除全部 ipynb，说明写进代码注释 | 只维护一份代码 |

**插曲**：`log.info("W的值是: ", W)` 报错 `not all arguments converted`。logging 不像 print 那样自动拼接参数，要写成 `log.info("W的值是: %s", W)`。

### ② 让训练过程看得见（11-06）

> 触发：「画图和训练是割裂开来的，理论上应该边训练边画图……这是最初始的例子，拟合过程需要肉眼直观地观察。」

**决定**：每一轮训练后就刷新图像，绘图写成公共方法供各 demo 复用。

**弯路**：改完之后只画出第一条线就停了，不是动画。我当时猜是子线程没暂停住主线程，**实际原因是 PyCharm 的 Plots 面板接管了图窗**。在设置里搜索 *Show plots in tool window* 并取消勾选即可。教训：找 IDE 设置时，直接用搜索框比按菜单一层层找快。现在公共绘图基类会自动切到 `MacOSX` 后端。

### ③ 让每个变量读得懂（11-08）

> 触发：读训练循环时一路卡住：W 是数还是数组？`dY_pred` 是谁对谁的导数？

**决定**：

- 每个变量都写类型注释，`Scalar` 表示一个数，`NDArray` 表示数组，并写明形状；
- 导数统一命名为 `d_loss_d_w`、`d_loss_d_y_pred`，名字本身说明「谁对谁求导」，所有 demo 一起改；
- 关键计算在注释里配一个中间算例，比如 `[1, −2, 3]` 平方后求平均，以及幂函数的求导规则；
- 循环整理成固定顺序：预测 → 损失 → 展示 → 梯度 → 更新。最终结果的轮次用 `epoch + 1` 表示，不另外引入计数变量。

### ④ 把绘图抽成结构（11-08）

> 触发：demo_01 和 demo_02 都在训练 `y = 3x`，只是画法不同。

**决定**：

- 把动态绘图合并进 demo_01，三个窗口同时更新：拟合直线、epoch-loss、W-loss；
- `FittingPlot` 作为抽象基类，三个子类各自实现 `update()`；
- **不另外定义 `TrainingPlots` 这样的协调类**，demo 直接调用各个子类，少一层抽象；
- 三个窗口并排排开，不叠在一起，便于同时对照。

关键约束：三个窗口展示的必须是**同一时刻**的 w 和 loss。

### ⑤ 用实验问题决定 demo 的取舍（11-08）

> 触发：原来的 6 个 demo 有重复，有的说不清自己在演示什么。

**原则**：每个 demo 只回答一个问题；回答不了新问题的就删掉。

| 原来 | 处理 | 理由 |
|---|---|---|
| 梯度下降、拟合过程 | 删除 | 内容已被 demo_01 的三个窗口覆盖 |
| 偏置 | 重写为 demo_02 | 两个模型共用**一套训练循环**，靠 `Linear(use_bias=False)` 区分；对称样本中刻意包含 `(0, 5)` 这个点 |
| 两层模型 | 新增 demo_04，单独一个文件 | 由「backward 为什么返回 dX」引出，专门演示梯度怎样跨层传递 |
| 近似拟合 | 改为学习率对照 demo_03 | 两条 epoch-loss 曲线，加一张带参数轨迹的 W-loss 曲线；只看 loss 曲线看不出参数在跳跃 |
| 封装 Linear / SGD | 删除 | 用法已被 demo_02 和 demo_04 覆盖 |

最后把 demo 重新编号为连续的 01～04，并更新 README。
