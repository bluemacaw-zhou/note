# MongoDB 副本集正确连接方式

## 目标
找到副本集模式下客户端（Compass / Spring Boot）的正确连接部署方式，替代当前的 directConnection 绕过方案。

---

## 问题背景

**现象**：Compass 或 Spring Boot 连接时报错 `ETIMEDOUT 192.168.x.x`，实际填写的 IP 是 `10.106.x.x`。

**根本原因**：MongoDB 副本集有"自发现"机制，客户端连接后会被重定向到副本集内部配置的地址。若内部配置的是私有 IP，外部客户端就会被引导到一个无法访问的地址。

---

## 已知的解决方向

### ❌ 直连绕过（错误方式，不应作为正式部署方案）

虽然能用，但绕过了副本集的自发现机制，等于放弃了副本集的高可用能力。

- Spring Boot：URI 加 `?directConnection=true`
- Compass：Advanced Options → 勾选 Direct Connection

### ✅ 正确方式（待验证）

修正副本集内部的成员地址配置，使其与外部可访问的地址一致：

```bash
docker exec -it mongodb mongosh -u admin -p admin --authenticationDatabase admin
cfg = rs.conf();
cfg.members[0].host = "10.106.51.218:27017";  # 改为外部可访问的 IP
rs.reconfig(cfg);
```

**但这只解决了已部署的情况。** 根本问题是：
- 如何在 docker-compose 初始化阶段就配置正确的对外地址？
- 跨网络环境（开发机 / 服务器）切换时如何保持配置正确？
