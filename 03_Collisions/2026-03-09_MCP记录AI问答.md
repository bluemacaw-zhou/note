# MCP 记录 AI 问答并提交 GitHub

## 目标
构建跨平台的 AI 知识归档系统，统一记录多端 AI 对话（CLI / Web / App）并自动提交到 GitHub。

---

## 核心碰撞点

**痛点**：多端 AI 对话记录零散，难以沉淀。

**架构演进**：
- 初期想法：各端分别采集
- 优化思路：利用 MCP（Model Context Protocol）作为统一接口
- 后端抉择：跳过本地文件限制，直连 GitHub API
- 定位：GitHub 是数据库，Obsidian 只是其中一个展示终端

---

## 关键洞见

- 笔记系统的价值不在于"存储"，而在于"碰撞"的过程
- AI 不应只是回答者，而应是自动化的"首席记录官"
- 统一使用 MCP 可以消除不同 AI 客户端（Claude Code / OpenCode 等）之间的行为差异

---

## 已有基础

- `sync_to_github.py`：已实现直连 GitHub API 的 commit 逻辑（blob → tree → commit → ref）
- `README.md`：AI 分类指南，MCP 归档时读取此文件确定归档路径

---

## 结论（2026-03-24）

**已放弃，需求被碎片化学习工作流完全替代。**

原始痛点（多端 AI 对话记录零散）已通过以下方式解决，不再需要专门的 MCP 归档服务器：

- **结构化笔记**：openclaw `save-note` skill → agent 直接整理内容 → 写入 Obsidian vault
- **统一触发**：Slack → openclaw agent → 调用 skill，不需要 MCP 作为中间层
- **分类归档**：agent 理解 vault 目录结构（01_Curiosities / 02_Spheres / 03_Collisions / 04_Chronicles），自主决定写入路径
- **GitHub 同步**：Obsidian vault 本身是 git repo，commit/push 由用户或 agent 手动触发

当初认为需要 MCP 解决的"跨端行为差异"问题，实际上 openclaw skill 机制已经解决了。
