# OpenClaw 本地部署与智谱 GLM 配置

> OpenClaw 是开源 AI 智能体平台（MIT License），通过各类 IM 渠道收发消息驱动 AI Agent 执行任务。
> 个人 fork：https://github.com/bluemacaw-zhou/openclaw
> 本地路径：`~/workspace/openclaw`

---

## 一、环境准备

### 依赖版本要求

| 工具 | 要求 | 说明 |
|------|------|------|
| Node.js | ≥ 22.16.0 | 项目 `package.json` engines 字段声明 |
| pnpm | 10.23.0 | `packageManager` 字段锁定版本 |
| bun | 任意 | 部分构建步骤使用 |
| git | 任意 | 版本管理 |

### 安装命令

```bash
# pnpm（锁定版本）
npm install -g pnpm@10.23.0

# bun（安装脚本自动写入 ~/.zshrc）
curl -fsSL https://bun.sh/install | bash
```

## 二、从源码构建

```bash
git clone https://github.com/bluemacaw-zhou/openclaw.git ~/workspace/openclaw
cd ~/workspace/openclaw

# 安装依赖（1321 个包，约 2 分钟）
pnpm install

# 构建（生成 dist/ 产物）
pnpm build
```

构建产物在 `dist/`，入口为 `dist/entry.js`。

> **注意**：`@discordjs/opus`、`@tloncorp/tlon-skill` 的 build scripts 默认被忽略，不影响核心功能。

## 三、如何发现 Provider 和模型配置（探索过程）

拿到一个新的 OpenClaw 环境，什么文档都没有的情况下，按以下顺序探索：

### 第一步：看 `onboard --help`

这是最直接的信息源，所有支持的 provider 都列在 `--auth-choice` 参数的枚举值里：

```bash
node dist/entry.js onboard --help
```

输出中找到 `--auth-choice` 一行，所有支持的 provider 都在里面，例如：

```
--auth-choice ... zai-api-key|zai-coding-global|zai-coding-cn|zai-global|zai-cn ...
```

命名规律：
- `zai-*` 开头 → 智谱 Z.AI 系列
- `cn` 结尾 → 国内端点
- `coding` → Coding Plan（有专属优惠定价）
- 其他类推：`gemini-api-key`、`moonshot-api-key`、`ollama` 等

光看这个枚举就能推断出选哪个，不需要查外部文档。

### 第二步：配置后用 `models` 命令查可用模型

```bash
node dist/entry.js models
```

Gateway 启动后，此命令会从 provider 拉取模型列表，直接显示可用的模型 ID。不需要事先知道模型名称。

### 第三步（按需）：看源码

如果 help 信息不够，直接搜源码：

```bash
grep -r "zai" ~/workspace/openclaw/src --include="*.ts" -l
```

### 第四步（按需）：查 provider 官方文档

部分 provider 有专门的 OpenClaw 集成章节，例如智谱：`docs.bigmodel.cn/cn/guide/develop/openclaw`。

> **探索优先级：`--help` → `models` 命令 → 源码 → 官方文档**
> 大多数情况下前两步就够了。这个顺序适用于 OpenClaw 所有配置项的探索。

## 四、配置智谱 GLM

### 环境变量

在 `~/.zshrc` 中添加：

```bash
export ZHIPUAI_API_KEY=<your_api_key>
```

> ⚠️ 注意：API Key 末尾不能有多余字符（如 `)`），否则返回「令牌已过期或验证不正确」。

验证 key 是否有效：

```bash
curl -s -X POST "https://open.bigmodel.cn/api/paas/v4/chat/completions" \
  -H "Authorization: Bearer $ZHIPUAI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"glm-4-flash","messages":[{"role":"user","content":"回复 API正常 四个字"}],"max_tokens":20}'
```

### 非交互式 onboard 配置

```bash
cd ~/workspace/openclaw

node dist/entry.js onboard \
  --non-interactive \
  --accept-risk \
  --auth-choice zai-coding-cn \
  --zai-api-key "$ZHIPUAI_API_KEY" \
  --skip-channels \
  --skip-skills \
  --skip-daemon \
  --skip-search \
  --skip-ui \
  --skip-health
```

配置写入 `~/.openclaw/openclaw.json`，模型默认为 `zai/glm-5`。

**`--auth-choice` 可选值（智谱相关）：**

| 值 | 说明 |
|----|------|
| `zai-coding-cn` | 智谱 Coding Plan 国内端点（推荐） |
| `zai-cn` | 智谱标准国内端点 |
| `zai-api-key` | 通用 API Key 方式 |

## 五、启动 Gateway

### 开发模式（watch，源码改动自动重建）

```bash
cd ~/workspace/openclaw
pnpm gateway:watch
```

### 直接启动（前台，不监听源码变化）

```bash
node dist/entry.js gateway run
```

### 开机自启动（launchd 服务，推荐生产使用）

OpenClaw 内置 launchd 支持，一条命令安装并注册为 LaunchAgent：

```bash
# 安装为系统服务（开机自启）
node dist/entry.js gateway install

# 启动
node dist/entry.js gateway start

# 停止
node dist/entry.js gateway stop

# 重启
node dist/entry.js gateway restart

# 卸载服务
node dist/entry.js gateway uninstall
```

安装后生成：
- LaunchAgent plist：`~/Library/LaunchAgents/ai.openclaw.gateway.plist`
- 日志文件：`~/.openclaw/logs/gateway.log`

### 查看服务状态

```bash
node dist/entry.js gateway status
```

输出示例：
```
Runtime: running (pid 63331, state active)
RPC probe: ok
Listening: 127.0.0.1:18789
```

### 查看日志

```bash
# 实时滚动日志（主日志，按日期）
tail -f /tmp/openclaw/openclaw-$(date +%Y-%m-%d).log

# 服务日志（launchd 管理时）
tail -f ~/.openclaw/logs/gateway.log

# 查看 channel 最近日志
node dist/entry.js channels logs

# 查看 gateway 状态 + 健康检查
node dist/entry.js status
```

Web Control UI 地址：`http://127.0.0.1:18789`

## 六、CLI Chat 测试命令

### 基本对话

```bash
# 指定 main agent 发送消息
node dist/entry.js agent --agent main --message "你好"

# 指定 session ID
node dist/entry.js agent --session-id <id> --message "消息内容"

# 指定收件人（E.164 格式电话号码）
node dist/entry.js agent --to +8613800138000 --message "消息内容"
```

> **注意**：`--local` 和单独 `--message` 不够，必须至少指定 `--agent`、`--session-id`、`--to` 之一。

### 其他常用命令

```bash
# 查看帮助
node dist/entry.js --help
node dist/entry.js agent --help

# 查看已连接 channel 状态
node dist/entry.js status

# 查看可用模型
node dist/entry.js models

# 查看 session 列表
node dist/entry.js sessions

# 安全审计
node dist/entry.js security audit --deep
```

## 七、QQ Channel 接入（探索过程）

### 踩坑：`channels add --channel qqbot` 无效

QQ 开放平台文档给出的指令是：

```bash
openclaw plugins install @tencent-connect/openclaw-qqbot@latest
openclaw channels add --channel qqbot --token "AppID:ClientSecret"
```

实际执行时两个问题：

1. **没有全局 `openclaw` 命令**：从源码运行需改为 `node dist/entry.js`
2. **`channels add --channel qqbot` 报 Unknown channel**：`channels add` 的 `--channel` 枚举是硬编码的内置列表，不识别第三方插件

### 排查过程

**第一步**：确认插件已加载

```bash
node dist/entry.js plugins list
```

输出最后一行可以看到插件 ID 是 `openclaw-qqbot`，状态 `loaded`——插件没问题，是命令不对。

**第二步**：看插件源码找真正的配置入口

```bash
# 找到 onboarding.ts，看配置写入哪个路径
grep -n "channels" ~/.openclaw/extensions/openclaw-qqbot/src/onboarding.ts
```

发现配置写在 `openclaw.json` 的 `channels.qqbot` 下，字段为 `appId` + `clientSecret`（token 里 `:` 前后两段），不是 `channels add` 命令处理的。

**第三步**：直接写配置文件

```json
// ~/.openclaw/openclaw.json 中添加
{
  "channels": {
    "qqbot": {
      "enabled": true,
      "appId": "<AppID>",
      "clientSecret": "<ClientSecret>",
      "markdownSupport": true
    }
  }
}
```

重启 gateway 后验证：

```bash
node dist/entry.js channels status
# 输出：QQ Bot default: enabled, configured, running, connected
```

### 结论

`channels add` 只支持内置 channel（telegram/discord 等），**第三方插件的配置需要直接写 `openclaw.json`**，具体字段看插件的 `onboarding.ts` 源码。
