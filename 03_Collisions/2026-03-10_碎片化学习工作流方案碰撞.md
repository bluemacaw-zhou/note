# 碎片化学习工作流

碎片时间的学习内容密度高，但事后复盘成本大。本工作流目标是把"听过就忘"变成"听完即有笔记"，核心思路是**让 Mac Mini 的算力接管学习内容的加工工作**。

当前规划三条流水线：

---

## 一、课程音频 → AI 笔记

**问题**：上课时全神贯注听讲，课后复习整理耗时长，且依赖记忆还原。

**方案**：播放课程时由 Mac 录制系统音轨，课程结束后自动转录为文字，交由 Claude API 生成结构化笔记，直接写入 Obsidian。

**流水线**：
```
课程播放 → BlackHole 捕获音轨 → ffmpeg 录制 → whisper.cpp 转录 → SRT 字幕文件
```

**进度**：
- [x] BlackHole + 多输出设备配置
- [x] ffmpeg 录制链路验证
- [x] whisper.cpp 编译（Metal GPU 加速）
- [x] medium 模型转录验证（金融类课程效果良好）
- [x] 一键录制转录脚本（`~/whisper/record_and_transcribe.sh`）

**TODO（锦上添花）**：
- [ ] 接入 AI 对转录文字做校对润色
- [ ] AI 生成结构化笔记自动写入 Obsidian

## 二、YouTube 视频 → 中英双语字幕 → Jellyfin 观看

**问题**：想看英文技术/知识视频，纯英文吸收慢，想有中英双语字幕辅助理解，并纳入 Jellyfin 统一管理。

**方案**：用 Tube Archivist 下载 YouTube 视频，用 whisper.cpp 生成英文字幕，再调翻译接口生成中文字幕，双轨字幕嵌入后推送给 Jellyfin 播放。

**流水线**：
```
YouTube 视频 → Tube Archivist 下载 → whisper.cpp 转录（英文 SRT）→ 翻译 API → 双语 SRT → Jellyfin
```

**待考量**：
- whisper.cpp 转录生成的字幕时间轴，是基于音频文件的起始点计算的。若音频提取时有偏移，或视频本身有片头，字幕时间轴可能与视频画面不对齐，需验证对齐方案。

**进度**：
- [x] Tube Archivist 部署完成（:8000）
- [x] Tube Archivist ↔ Jellyfin 集成待验证
- [ ] whisper.cpp 生成英文字幕流程
- [ ] 验证字幕时间轴与视频对齐
- [ ] 中英双语字幕合并方案
- [ ] 自动化脚本

## 三、PDF → 电子书 → 微信读书朗读

**问题**：技术书籍、研究报告多为 PDF 格式，微信读书对 PDF 的朗读体验差（无法流畅断句）。转换为 EPUB 后，微信读书可流畅朗读，通勤时"听书"效率大幅提升。

**方案**：用 Pandoc 或 Calibre 将 PDF 转为 EPUB，上传至微信读书，利用其 TTS 朗读。

**流水线**：
```
PDF → Pandoc/Calibre → EPUB → 上传微信读书 → 朗读
```

**进度**：
- [ ] 工具选型（Pandoc vs Calibre，对比排版还原度）
- [ ] 批量转换脚本
- [ ] 验证微信读书朗读效果
