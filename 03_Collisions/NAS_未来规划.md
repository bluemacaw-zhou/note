## 一、磁盘扩容

当前 Mac Mini 内置磁盘容量有限，媒体库增长后需要解决存储问题。两条路：

### 方案 A：给 Mac Mini 加外接磁盘

- 通过 Thunderbolt / USB 接外置硬盘或硬盘盒
- 优点：成本低，操作简单，不需要更换机器
- 缺点：外置盘速度和稳定性不如内置 SATA；长期运行发热问题
- 适合：短期过渡，验证阶段存储临时扩容

### 方案 B：迁移到 x86 小主机（推荐）

- 购买支持 SATA 接口的 x86 小主机，直连机械硬盘
- 速度快，支持 RAID，适合长期运行
- 可同步实现全屋透明代理（见下）

**推荐配置：**

| 设备 | 型号 | 参考价 |
|------|------|--------|
| x86 小主机 | 倍控 N100（16GB，4口 2.5G） | ~1000 元 |
| NAS 硬盘 × 2 | 西数红盘 WD Red Plus 4TB | ~600 元/块 |
| 合计 | | ~2200 元 |

N100 核显支持硬件转码，相比 Mac Mini 软件转码可大幅降低 CPU 占用。

## 二、全屋透明代理（依赖 x86 小主机）

迁移到 x86 小主机后，可将其同时做软路由，实现全屋透明代理。

**原理：**
```
所有设备（手机/电视/电脑）无需任何配置
    ↓ 流量经过软路由
Mihomo（代理引擎）
    ├── 国内 IP → 直连
    ├── 国外 IP → 代理节点
    └── 广告域名 → 拦截
```

相比现在每台设备单独开代理，透明代理的优势：
- 设备零配置，路由器层统一处理
- 电视等无法安装代理的设备也能走代理
- 广告拦截对全屋生效

**依赖：**
- x86 小主机（多网口做路由）
- Mihomo + iptables 配置
- 与 OpenVPN 不冲突（OpenVPN 走内网段直通，不经代理）

## 三、AI 探索：OpenClaw 赋能媒体系统

媒体系统的 AI 切入点：用自然语言控制下载，而非手动操作 Sonarr/Radarr Web UI。

### 设想的链路

```
手机 QQ："帮我下载小猪佩奇全集"
    ↓
NapCatQQ（QQ Bot 框架，OneBot 协议）
    ↓
Spring Boot Bot 服务
    ↓
OpenClaw → Claude API 解析意图
    → { title: "小猪佩奇", type: "animation", season: "all" }
    ↓
调用 Sonarr/Radarr API 添加任务
    ↓
QQ 回复："已添加，正在下载"
```

### 思考方向

- **意图解析**：Claude 从自然语言提取结构化的下载意图（剧名、类型、季数）
- **多轮对话**：模糊请求时反问确认（"是哪个版本的小猪佩奇？"）
- **状态播报**：下载完成后主动通知
- **更多动作**：不只是下载，还可以查看下载进度、删除任务、推荐相似内容

### 部署要求

- NapCatQQ 部署在 K8s（Namespace: bot）
- OpenClaw 部署在独立 Namespace（ai），NetworkPolicy 隔离，只允许访问 Claude API
- 不影响现有媒体服务的稳定性
