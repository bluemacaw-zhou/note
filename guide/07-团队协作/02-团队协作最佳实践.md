## Git 协作流程

### 1. 分支策略

**推荐策略**：
```
main (主分支)
├── develop (开发分支)
│   ├── feature-xxx (功能分支)
│   ├── bugfix-xxx (修复分支)
│   └── hotfix-xxx (紧急修复)
```

**分支命名**：
- `feature/功能名称`：新功能开发
- `bugfix/问题描述`：Bug 修复
- `hotfix/紧急问题`：生产环境紧急修复
- `docs/文档更新`：文档更新

### 2. 工作流程

**日常流程**：
```bash
# 1. 拉取最新代码
git pull origin main

# 2. 创建功能分支
git checkout -b feature/new-function

# 3. 提交修改
git add .
git commit -m "feat: 添加新功能"

# 4. 推送分支
git push origin feature/new-function

# 5. 创建 Pull Request
# 在 Gitea/GitHub 创建 PR

# 6. 代码审查通过后合并
```

**提交规范**：
```bash
# 格式
<type>(<scope>): <subject>

<body>

<footer>
```

**类型 (type)**：
- `feat`：新功能
- `fix`：Bug 修复
- `docs`：文档更新
- `style`：格式调整
- `refactor`：重构
- `test`：测试
- `chore`：工具/依赖

**示例**：
```bash
feat(auth): 添加用户登录功能

- 实现用户名密码登录
- 添加 JWT token 验证
- 完善错误处理

Closes #123
```

## 协作规范

### 1. 文件编辑规范

**避免同时编辑**：
- 使用 `git status` 检查他人修改
- 大文件编辑前先沟通
- 使用分支隔离开发

**编辑锁定**（可选）：
```markdown
---
editing: true
editing_by: 张三
editing_since: 2026-03-06
---
```

### 2. 同步频率

**推荐频率**：
- **开发阶段**：每 1-2 小时同步一次
- **提交前**：必须先 pull 再 push
- **下班前**：确保所有修改已推送

**自动同步**：
```yaml
# obsidian-git 配置
Auto commit interval: 30
Auto pull interval: 5
Auto-push interval: 30
```

### 3. 沟通机制

**修改通知**：
```markdown
> [!info] 修改说明
> 修改了 API 文档的认证部分
> - 作者：张三
> - 时间：2026-03-06 14:30
> - 原因：添加新的认证方式
```

**重要变更**：
- 在团队群通知
- 在文档中注明变更
- 相关人员确认后合并

## 冲突解决

### 1. 预防冲突

**最佳实践**：
1. **频繁同步**：定期 pull 最新代码
2. **小步提交**：不要长时间不提交
3. **明确分工**：避免多人同时修改同一文件
4. **使用分支**：功能开发使用独立分支

### 2. 解决冲突

**遇到冲突时**：
```bash
# 1. 拉取最新代码
git pull origin main

# 2. 如果有冲突，Git 会标记
# Auto-merging file.md
# CONFLICT (content): Merge conflict in file.md

# 3. 打开文件，查找冲突标记
<<<<<<< HEAD
你的内容
=======
他人的内容
>>>>>>> feature-branch

# 4. 手动解决冲突
保留正确的内容，删除标记

# 5. 标记为已解决
git add file.md

# 6. 完成合并
git commit
```

**冲突解决技巧**：
- 使用对比工具（如 VS Code）
- 与原作者沟通确认
- 保留双方的修改意图
- 测试解决后的内容

## 权限管理

### 1. Gitea 权限

**仓库角色**：
| 角色 | 权限 |
|------|------|
| Owner | 所有权限 |
| Maintainer | 读写 + PR 合并 |
| Developer | 读写 |
| Reporter | 只读 + Issue |

**分支保护**：
```yaml
Protected Branches:
  main:
    - Require PR: yes
    - Require review: 1
    - Block force push: yes
```

### 2. 文件夹权限

**使用 README 说明**：
```markdown
# 技术文档

> [!warning] 权限说明
> - 只读：所有人
> - 编辑：技术团队
> - 审核：技术负责人
```

**使用子模块**：
- 敏感内容使用独立仓库
- 通过 Git Submodule 集成
- 单独设置访问权限

## 常见问题

### Q1：如何处理多人同时编辑？

**A**：
- 使用实时协作工具（如 Gitea 的 Collaborative Editing）
- 或约定编辑时间段
- 使用分支隔离开发

### Q2：如何找回历史版本？

**A**：
```bash
# 查看历史
git log --follow file.md

# 恢复到某个版本
git checkout <commit> -- file.md
```

### Q3：如何追踪文档修改？

**A**：
```bash
# 查看文件修改历史
git log -p file.md

# 查看谁修改了某行
git blame file.md
```
