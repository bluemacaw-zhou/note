## 设计原则

### 1. 渐进式组织

**由下至上**：
```
收件箱 → 处理 → 归档 → 索引
```

- **收件箱**：快速捕获
- **处理**：分类整理
- **归档**：长期存储
- **索引**：快速检索

### 2. 分层架构

```
知识库/
├── 📥 收件箱/          # 临时内容
├── 📁 项目/           # 活跃项目
├── 📚 知识/           # 结构化知识
├── 👥 团队/           # 协作内容
├── 🗄️ 归档/           # 历史内容
└── 🔗 索引/           # 导航索引
```

### 3. 模块化设计

**独立模块**：
- 每个目录可独立运作
- 模块间通过双链连接
- 便于权限控制和版本管理

## 命名规范

### 文件命名

**日期格式**：
```
YYYY-MM-DD-标题.md
例：2026-03-06-团队会议.md
```

**项目命名**：
```
编号-项目名称
例：001-用户认证系统
```

**文档类型**：
```
类型-标题
例：PRD-用户登录功能
例：API-用户接口文档
```

### 文件夹命名

**数字前缀**：
```
01-待办
02-进行中
03-已完成
```

**表情符号**：
```
📁 项目
📚 文档
📝 笔记
✅ 任务
```

## 元数据体系

### Frontmatter 模板

**项目文档**：
```yaml
---
title: 文档标题
project: 项目名称
type: 需求/设计/会议
status: 草稿/评审中/已批准
assignee: 负责人
due_date: 2026-03-31
tags: [项目, 需求]
---
```

**会议记录**：
```yaml
---
title: 会议标题
date: 2026-03-06
attendees: [张三, 李四, 王五]
type: 周会/评审/讨论
action_items:
  - task: 任务1
    owner: 张三
    due: 2026-03-10
---
```

**知识文档**：
```yaml
---
title: 知识标题
category: 技术/业务/流程
difficulty: 入门/进阶/专家
related:
  - [[相关文档1]]
  - [[相关文档2]]
tags: [技术, 知识]
last_updated: 2026-03-06
---
```

## 最佳实践

> [!tip] 设计建议
> 1. **从简到繁**：先建立基本结构，再逐步细化
> 2. **保持一致**：使用统一的命名和模板
> 3. **定期审查**：定期清理和调整结构
> 4. **团队共识**：确保团队理解并遵守规范
