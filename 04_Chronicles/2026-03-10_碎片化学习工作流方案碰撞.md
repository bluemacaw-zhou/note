# 碎片化学习工作流

碎片时间的学习内容密度高，但事后复盘成本大。本工作流目标是把"听过就忘"变成"听完即有笔记"，核心思路是**让 Mac Mini 的算力接管学习内容的加工工作**。

当前规划三条流水线：

---

## 一、课程音频 → AI 笔记

**问题**：上课时全神贯注听讲，课后复习整理耗时长，且依赖记忆还原。

**方案**：播放课程时由 Mac 录制系统音轨，课程结束后自动转录为文字，交由 Claude API 生成结构化笔记，直接写入 Obsidian。

**流水线**：
```
课程播放 → BlackHole 捕获音轨 → ffmpeg 录制 → whisper.cpp 转录 → SRT 字幕文件
```

**进度**：
- [x] BlackHole + 多输出设备配置
- [x] ffmpeg 录制链路验证
- [x] whisper.cpp 编译（Metal GPU 加速）
- [x] medium 模型转录验证（金融类课程效果良好）
- [x] 一键录制转录脚本（`~/whisper/record_and_transcribe.sh`）

**AI 整合（2026-03-24 完成）**：
- [x] AI 对转录文字做校对润色 → `transcribe` skill 生成 .srt，传给 `save-note` skill 用 Gemini 整理
- [x] AI 生成结构化笔记自动写入 Obsidian → `save-note` skill：`cat transcript.srt | gemini -p "整理为结构化笔记" > ~/workspace/note/...`

执行方式：Slack 触发 → agent 调用 skill，不是完全自动化，但流程固化。

## 二、YouTube 视频 → 中英双语字幕 → Jellyfin 观看

**问题**：想看英文技术/知识视频，纯英文吸收慢，想有中英双语字幕辅助理解，并纳入 Jellyfin 统一管理。

**实际流水线**（2026-03-16 验证完成）：
```
YouTube 视频
  → TubeArchivist 下载 + 抓取 YouTube 字幕（user 或 auto）
  → Claude Code 翻译 SRT（逐段翻译，100 条/批）
  → 双语 SRT（英文在上，中文在下，同一字幕条目）
  → 放入视频同目录，Jellyfin 自动识别
```

**关键发现**：
- TubeArchivist **没有**内置 Whisper，字幕来源是 YouTube 自带字幕（两种模式）：
  - `subtitle_source: user` → YouTube 人工上传字幕，质量最高
  - `subtitle_source: auto` → YouTube 自动生成字幕（YouTube ASR），技术类英文视频质量可用
- 下载的 SRT 放在 `~/nas/media/youtube/<channel_id>/<video_id>.srt`，与视频同目录，Jellyfin 直接识别。
- 时间轴天然对齐（YouTube 字幕本身就是对齐的）。
- **字幕缺失场景**：若该视频没有 YouTube 字幕（无 user，无 auto），则需要单独跑 whisper.cpp 转录，走流水线一的音频→SRT 方案。

**双语 SRT 格式**：
```
1
00:00:00,000 --> 00:00:05,320
Have you been thinking about maybe switching away from Vim over to Doom
你是否一直在考虑从 Vim 切换到 Doom
```

**Jellyfin 集成**（2026-03-16 完成）：
- 插件：`TubeArchivist Metadata` v1.4.4，手动下载安装到 `~/nas/config/jellyfin/plugins/TubeArchivistMetadata/`
- 插件配置：`TubeArchivistUrl = http://tubearchivist:8000`，API Key 从容器内 Django shell 获取
- 获取 TA API Key 命令：
  ```bash
  docker exec media-tubearchivist bash -c "
  cd /app && python manage.py shell -c \"
  from user.models import Account
  from rest_framework.authtoken.models import Token
  for u in Account.objects.all():
      t, _ = Token.objects.get_or_create(user=u)
      print(f'{u.name}: {t.key}')
  \""
  ```
- 添加媒体库：Jellyfin → Libraries → Add → 类型选 `Shows`，路径填 `/media/youtube`，刮削器只勾 `TubeArchivist Metadata`

**翻译方案（2026-03-24 实际落地）**：
- 工具链固化到 openclaw skills + `~/dl-support/` 脚本
- 触发方式：Slack 发链接 → agent 执行全流程

实际流水线（无 YouTube 字幕时）：
```
视频 .mp4
  → ffmpeg 提取 WAV（16kHz mono）
  → whisper-cli medium 模型 → .en.srt（英文转录）
  → check_whisper.py 校验
  → Gemini（translate-sub skill）→ .zh.srt
  → check_translation.py 校验条目数
  → merge_bilingual.py → .srt（双语合并）
  → 放入视频同目录，Jellyfin 自动识别
```

辅助脚本（`~/dl-support/`）：

| 脚本 | 作用 |
|------|------|
| `check_whisper.py` | 校验 Whisper 输出完整性（重复段、空段等） |
| `check_translation.py` | 校验译文条目数与原文匹配 |
| `merge_bilingual.py` | 按时间轴合并英中 SRT，输出双语字幕 |

**自动化状态**：
- [x] 脚本化翻译流程（`transcribe` + `translate-sub` + `~/dl-support/` 三步走）
- [x] 字幕文件自动放入视频同目录
- [ ] TubeArchivist 下载完成后自动触发（仍需手动发 Slack）

## 三、PDF → 电子书 → 微信读书朗读

**问题**：技术书籍、研究报告多为 PDF 格式，微信读书对 PDF 的朗读体验差（无法流畅断句）。转换为 EPUB 后，微信读书可流畅朗读，通勤时"听书"效率大幅提升。

**PDF 类型**：
- 纯中文 / 纯英文 / 中英混合（双语对照，段落交替排版）
- 文字型 PDF（可选中）或扫描版（需 OCR）

**流水线**：
```
PDF
  → PyMuPDF 提取文本块（pdf_parser.py）
  → 语言检测（段落级别，CJK 字符占比）
  ├── 双语对照 PDF → split.py → 中文 EPUB [+ 英文 EPUB]
  ├── 纯英文 PDF   → translate_pdf.py → Ollama 翻译 → 中文 EPUB
  └── 上传微信读书 → upload.py → Playwright 自动化
```

详细安装与使用说明见 [[2026-03-18_pdf2epub工具指南]]。

**使用方法**：
```bash
# 统一入口，自动检测语言，交互式引导
cd ~/pdf2epub
uv run python main.py <pdf文件>

# 上传 EPUB 到微信读书（Playwright Firefox + 终端扫码）
uv run python upload.py <epub文件>
```

## 基础组件：Ollama 本地 AI 推理

三条流水线的翻译/AI 处理统一走 Ollama，不依赖云端 API。

```
沉浸式翻译（网页）  ─┐
SRT 翻译脚本        ─┼──→  Ollama  localhost:11434
PDF 翻译脚本        ─┘
```

详细部署说明见 [[2026-03-18_Ollama本地部署指南]]。

**核心要点**：
- 宿主机直装（不走 Docker），保留 Metal GPU 加速
- 模型目录 `~/.ollama/models`，与 `~/nas/` 完全独立
- 空闲 5 分钟自动卸载模型，不长期占内存
- API：`localhost:11434`，兼容 OpenAI 格式
- 推荐模型（32GB）：`qwen2.5:32b`（翻译）、`qwen2.5vl:32b`（视觉）
